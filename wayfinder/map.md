# Локальная запись и расшифровка встреч на Linux

## Destination

План, по которому за одну сессию пишется демон `meetrec`: он сам замечает звонок, пишет дорожки `me` и `them`, расшифровывает их локально и кладёт `transcript.md` и `summary.md` в папку встречи. Все решения приняты, осталось писать код.

## Notes

- Машина: Ryzen 5 5600H (AVX2), без NVIDIA, 14 ГиБ RAM (свободно ~4,6), PipeWire 1.0.5, Cinnamon/X11, fish; есть `notify-send`, `uv`, `systemd --user`, `claude`.
- Контекст и альтернативы: `~/src/work-repo/docs/amanu-research.md`.
- Принятые при постановке рамки:
  - Python-скрипт через `uv`, демон под `systemd --user`, `pw-record` и расшифровка — подпроцессы.
  - Звонок = чужое приложение открыло поток записи с микрофона; конец — поток закрыт дольше 30 с.
  - Пишем сразу, `notify-send` на старте и стопе, встречи короче 2 мин удаляем.
  - `them` = monitor системного вывода целиком (браузер: Meet, Zoom web; приложение Zoom).
  - Только русский: GigaAM-v3.
  - Папка встречи `~/Recordings/<YYYY-MM-DD-HHMM>/`: `me.wav`, `them.wav`, `transcript.md`, `summary.md` (+ `meta.json`, `*.tokens.tsv`); звук не удаляется.
  - Звук не покидает машину; текст транскрипта уходит в `claude -p`.
- Для grilling-тикетов: навыки `grilling` и `domain-modeling`.

## Decisions so far

Сводная спецификация для реализации: [SPEC.md](../SPEC.md).

- [Как заметить, что чужое приложение открыло микрофон](01-call-detection.md): `LC_ALL=C pactl subscribe` на `source-output` + снимок `pactl -f json list source-outputs`; звонок — не-monitor поток не от `meetrec`; свои `pw-record` метятся `application.name=meetrec`. Живым звонком не проверено.
- [Как писать две дорожки синхронно](03-two-track-capture.md): два `pw-record --rate 16000 --channels 1 --format s16` без `--target` (следуют за default-устройством), `them` с `stream.capture.sink=true`; сдвиг ~21 мс, дрейфа нет; при перелинковке BT теряются сэмплы; после SIGKILL чинить заголовок WAV.
- [Как transcribe.cpp расшифровывает русский на CPU](02-transcribe-cpp.md): `handy-computer/transcribe.cpp` v0.4.1, сборка `cmake` или колесо `transcribe-cpp`; модель `gigaam-v3-e2e-ctc-Q8_0.gguf` (272 МБ, с пунктуацией); длинное аудио режет сам; метки только по токенам (40 мс), сегменты собираем сами; оценка ~3–4 мин CPU на час дорожки (не замер); LocalVQE — отдельно, референс `them.wav`.
- [Почему система не замечает подключение наушников](10-headphones-detection.md): гипотеза — runtime PM кодека ALC256 теряет событие джека (`power_save=1`, `jackpoll_ms=0`); фикс для пользователя — `jackpoll_ms=,1000` в `snd_hda_intel`; на запись не влияет (`them` — monitor того же sink), демону хватит предупреждения при нулевом пике `me` дольше 60 с.
- [Замерить скорость GigaAM-v3 на этой машине](04-benchmark.md): 86 мин встречи — CPU 6 мин (14,7×, RSS 1,6 ГиБ), Vulkan на Vega 2:41 (33,5×), колесо `transcribe-cpp` без сборки; расшифровывать сразу после встречи: Vulkan, откат на CPU 4 потока под `nice -n 19`, дорожки по одной; качество годно для саммари, термины ломаются.
- [Что делать с эхом, если звонок идёт через динамики](05-echo.md): перед расшифровкой копия `me` чистится LocalVQE с `them` как референсом, `me.wav` не трогается; только если за встречу был порт Speaker (см. проверку LocalVQE); смену устройства посреди встречи только логируем.
- [Как демон ведёт встречу от старта до расшифровки](08-state-machine.md): Ожидание → Запись ⇄ Пауза → Закрыта → Обработка → Готова/Ошибка; обработка FIFO по одной и ждёт конца записи; состояние в `meta.json` папки встречи, после падения демон дочищает и доставляет в очередь; пауза по умолчанию 5 мин до проверки Firefox; ручных команд нет.
- [Вызывать transcribe.cpp как CLI или через Python-биндинг](09-cli-or-binding.md): биндинг `transcribe-cpp==0.4.1`, отдельный процесс на дорожку под `nice -n 19`; Vulkan, при сбое один повтор на CPU в 4 потока, затем Ошибка.
- [Как выглядит transcript.md](06-transcript-format.md): строки-фразы по паузе 1 с (до 15 с) и смене `me`/`them`, по времени начала, `**[ЧЧ:ММ:СС] me:** текст`, шапка с датой и длительностью; текст без чистки, термины правит саммари по глоссариям work-repo.
- [Что пишет summary.md и с каким промптом](07-summary.md): «Кратко / Решения / Задачи / Открытые вопросы» с метками времени; глоссарии work-repo на каждой встрече; `me` — Имя Фамилия; `claude -p` без инструментов и пользовательских настроек; сбой — встреча Готова без саммари, повтор вручную.
- [Какие ручные команды есть у meetrec](13-manual-commands.md): `meetrec status` и `meetrec redo <папка> [--transcript|--all]`; `redo` ставит в очередь через `meta.json` + `SIGUSR1` демону, сам не считает; метки слов хранятся в `*.tokens.tsv`.
- [Проверить, что LocalVQE не портит запись в наушниках](11-localvqe-headphones-check.md): портит — −13 дБ и гул, расшифровка не лучше; LocalVQE только если за встречу `active_port` был Speaker. Сборка — только `liblocalvqe.so` (`LOCALVQE_BUILD_SHARED`), без `libsndfile`, вызов через `ctypes`.
- [Как ставить и обновлять meetrec](14-install.md): `uv tool install --editable` на Python 3.14; идемпотентный `meetrec setup` (модели с sha256, сборка `liblocalvqe.so`, юнит `systemd --user`); данные в `~/.local/share/meetrec/`, необязательный `~/.config/meetrec/config.toml`; логи в journald; обновление вручную с прогоном эталонной встречи.
